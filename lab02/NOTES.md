**Рабочая папка** — папка с  файлами на компьютере, в которых я
редактирую текст. Git видит, что они изменились, но пока ничего не
сохраняет.

**Индекс**  — промежуточная зона. Туда я командой
`git add` кладу те изменения, которые хочу включить в следующий коммит.
Так можно выбрать, что именно сохранить.

**Коммит** — сохранённый снимок проекта с сообщением и автором. Коммиты
образуют историю, к любому из них можно вернуться.


## Git и GitHub

**Git** — программа для контроля версий. Она работает на компьютере
и хранит историю изменений локально, интернет ей не нужен.

**GitHub** — сервис в интернете, где можно хранить копию репозитория,
делиться ей и работать вместе. Git и GitHub — не одно и то же: Git — это
инструмент, а GitHub — одно из мест, где хранят репозитории Git.


## Использованные команды

- `git status` — показывает, какие файлы изменены, какие уже в индексе
  и на какой я ветке.
- `git diff` — показывает изменения между рабочей папкой и индексом,
  то есть то, что я ещё не добавил через `git add`.
- `git diff --staged` — показывает изменения между индексом и последним
  коммитом, то есть то, что попадёт в следующий коммит.

  
## Ветки

**Ветка** — это подвижный указатель на коммит. Она позволяет вести
отдельную линию изменений и не трогать основную.

При новом коммите в ветке её указатель сдвигается на новый коммит, а
остальные ветки остаются на месте. Поэтому в `main` изменения из другой
ветки не видны, пока их не объединят.

**Слияние** (`merge`) объединяет изменения одной ветки с другой. С
флагом `--no-ff` Git создаёт отдельный коммит слияния, и в истории
остаётся видно, что была ветка.
