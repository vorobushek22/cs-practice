# Журнал воркшопа

## Сравнение версий и поиск изменений

- `git log --oneline --stat` — показывает историю коммитов, у каждого
  коммита список изменённых файлов и число строк. Нужна, чтобы быстро
  увидеть, что и когда менялось.
- `git diff HEAD~2 HEAD -- lab03/calc.py` — показала разницу между
  первой и третьей версиями файла: добавились функции вычитания и
  умножения.
- `git show HEAD~1` — показала один коммит целиком: сообщение, автора
  и изменения в нём.
- `git log -S"def" --oneline -- lab03/calc.py` — нашла коммиты, в
  которых менялось число вхождений строки `def`, то есть где появились
  новые функции.
- `git blame lab03/calc.py` — показала для каждой строки файла коммит и
  автора, которые изменили её последними.

**Чем отличаются.** `git diff` сравнивает два состояния (две версии или
рабочую папку с индексом) и показывает только разницу. `git show`
показывает один коммит: его сообщение и изменения. `git log` показывает
список коммитов, то есть историю, без подробностей изменений (если не
добавить `--stat` или `-p`).


## Восстановление файла

- `git restore lab03/calc.py` — вернула файл к последней сохранённой
  версии (из индекса), несохранённые правки пропали безвозвратно.
- `git restore --source=HEAD~2 lab03/calc.py` — подставила в рабочую
  папку версию файла из коммита `HEAD~2`; `git diff` показал разницу
  с текущим состоянием.

**Чем отличаются.** Обычный `git restore` берёт версию из индекса
(фактически из последнего коммита) и откатывает правки. С
`--source=...` можно указать любой коммит, и файл возьмётся оттуда.
Несохранённые правки в обоих случаях перезаписываются и не
восстанавливаются, потому что Git их нигде не хранил.
